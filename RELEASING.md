# Releasing slap

A release is a tag. Pushing `vX.Y.Z` runs the Release workflow (`.github/workflows/release.yml`,
generated by [dist](https://opensource.axo.dev/cargo-dist/) from `dist-workspace.toml`), which:

1. builds `slap` for Apple silicon and Intel Macs;
2. publishes a GitHub release with both builds, a shell installer and checksums, its notes taken
   from the version's entry in `CHANGELOG.md`;
3. publishes `slap` to crates.io (`.github/workflows/publish-crates.yml`).

A version with a pre-release suffix, such as `v1.2.0-rc.1`, gets a GitHub pre-release and nothing
else.

## Steps

1. On a branch, set `version` in `Cargo.toml` and run `cargo check` to update `Cargo.lock`. A new
   feature bumps the minor version, a fix the patch, and a breaking change the major.
2. Draft the changelog entry with [git-cliff](https://git-cliff.org):

   ```sh
   git cliff --unreleased --tag vX.Y.Z --prepend CHANGELOG.md
   ```

   It lists the `feat`, `perf` and `fix` commits since the last tag. Then edit it for someone using
   slap: join commits that are one change, drop fixes to things never released, and say what a
   breaking change means for them. Set the date to the day you will tag.
3. Commit it as `chore: release vX.Y.Z`, open a pull request, and merge it once CI passes. Its
   `plan` check shows what the release will build.
4. Tag the merge commit and push the tag:

   ```sh
   git switch main && git pull
   git tag vX.Y.Z && git push origin vX.Y.Z
   ```

5. When the Release workflow is done, install the release with the installer command in the
   README and run `slap --version` and `slap 10s`.

## When something goes wrong

- **Never move or reuse a tag that was pushed.** A version on crates.io is permanent. Fix forward
  with a new patch version.
- **The crates.io job failed.** The GitHub release exists by then. Fix the cause and re-run the
  failed job from the workflow's page.
- **An authentication error from crates.io** means the `CARGO_REGISTRY_TOKEN` secret on
  `realzai/slap` has expired. Replace it with a crates.io token with the `publish-update` scope
  for `slap`.

## Changing how releases are made

Edit `dist-workspace.toml`, then run `dist generate` and commit the rewritten `release.yml`. To
update dist itself, install the new version and run `dist init`. The `plan` check fails on a pull
request whose `release.yml` does not match the configuration.
